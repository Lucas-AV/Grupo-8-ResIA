# Landing home page for the GitHub Pages site

## Context

The published site (`site/`) currently has six analysis pages plus an
`index.html` that is just a bare hub: a header paragraph and a grid of six
cards linking to each analysis. It presents fine to someone who already knows
what the project is, but says nothing about the project itself, the team, or
why it exists — someone landing on the URL cold has no framing.

Goal: turn `index.html` into an actual landing/presentation page: hero,
headline stats, team, then the existing card grid. No other page changes.

## Non-goals

- No changes to `genero.html`, `analise.html`-rendered pages (`modo`,
  `popularidade`, `visao-geral`, `correlacoes`, `mercado`), or `base.html`'s
  nav/footer structure.
- No new data pipeline — every number the new sections show already exists in
  `dataset_profile.json` or as hardcoded tile values already used for
  `mercado.html`.
- No i18n — page stays pt-BR, consistent with the rest of the site.

## Corrected numbers

`dataset_profile.json` (generated by `profile_dataset.py`) is the source of
truth: **31.819 faixas**, **32 gêneros** — not the "~114 mil faixas / 114
gêneros" the README previously (incorrectly) stated. The README has been
corrected to match; this spec and its implementation use the correct numbers
throughout.

## Page structure (`site/templates/index.html`)

Four sections in order, all inside the existing `.hub-header`/`.page`-style
container:

1. **Hero** — eyebrow "GRUPO 8 · RESIA", `<h1>De Dados a Recomendações</h1>`,
   subtitle referencing the ~31,8 mil faixas analyzed, two buttons: "Ver
   análises" (anchor `#analises`, scrolls to the card grid) and "Ver no
   GitHub" (external link to the repo).
2. **Destaques** — 4 stat tiles, reusing the existing `.tiles`/`.tile`
   component from `analise.html`: faixas analisadas (31.819), gêneros (32),
   crescimento do Brasil (+14,1%, same value already hardcoded in
   `mercado_html`'s tiles), mercado global 2025 (US$ 31,7bi, ditto).
3. **Equipe** — a new `.team-grid` component: one circular avatar
   (`github.com/<user>.png`), name, and a link to the GitHub profile, for
   each of the 5 members. Same people/usernames as the README's team table,
   no shields.io badge here (the avatar itself is already the link; a badge
   would be redundant chrome the README needs but a landing page doesn't).
4. **Análises** (`id="analises"`) — the existing card grid, unchanged
   markup, just now a later section on a longer page instead of the whole
   page.

## Data flow (`site/build_site.py`)

- New module-level `TEAM` list: 5 dicts of `{name, github}`, mirroring the
  README's team section. `github.com/<u>.png` and `https://github.com/<u>`
  are built from `github` in the template, not stored redundantly.
- New module-level `HOME_TILES` list: 4 dicts of `{label, value}` —
  faixas/gêneros computed from the already-loaded `dataset_profile.json`
  (reuse the same load already done for `visao_geral_html`, don't re-read the
  file twice — extract a small `load_dataset_profile(path)` helper returning
  the parsed dict, used by both the home tiles and the existing
  `total_tracks_display` / `load_profile_tiles` call sites), plus the two
  market values hardcoded the same way the existing `mercado_html` tiles are
  (no new constants file — matches the existing pattern in this codebase of
  hardcoding curated report numbers directly in `build_site.py`).
- `index.html`'s render call gains `team=TEAM, tiles=HOME_TILES` alongside
  the existing `analyses=ANALYSES`.

## Styling (`site/static/style.css`)

New rules only, nothing existing changes:

- `.hero` — padding, max-width matching `.hub-header`, centered or
  left-aligned text (implementer's call, follow the existing design tokens:
  `--ink`, `--ink-2`, `--accent-450`).
- `.hero-actions` — flex row of the two buttons; primary button uses
  `--accent-450` background, secondary is an outlined/ghost style using
  `--border-strong`.
- `.team-grid` — `display:grid; grid-template-columns:repeat(auto-fit,
  minmax(140px,1fr))`, each member centered, avatar `border-radius:50%`,
  reusing font tokens already defined (`--ink`, `--ink-2`).

## Testing / verification

- No automated tests for template/CSS output (consistent with how
  `templates/`/`static/` were treated in the original site spec) — build
  locally (`python site/build_site.py`), open `site/dist/index.html`, and
  confirm: hero renders with both buttons working (anchor scroll + external
  link), 4 destaque tiles show the correct numbers, 5 team members render
  with working avatar images and profile links, card grid still works
  unchanged, dark mode still looks correct.
- Existing `tests/test_build_site.py` keeps passing unmodified — the new
  `TEAM`/`HOME_TILES` constants and the `load_dataset_profile` extraction
  don't change `load_genre_rows`'s behavior.
